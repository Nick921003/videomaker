# 專案目標與使用者

2026-11-10 與使用者對過流程後建立。規劃、排工作、給建議前先讀這份；跟這份衝突的舊文件以這份為準。

## 目標

做出一條**標準化的教材製作流程**：教材進來，AI 整理內容、寫好文本，再從現成的風格與元件裡挑，產出影片（以及講義 PPT、心智圖）。每支片不重寫程式，能做什麼由元件目錄決定。

## 使用者

| 誰 | 怎麼用 | 有沒有人審 |
|---|---|---|
| 老師 | 丟進教材（md、pdf），先看內容架構與審片版，確認或客製後才完整產出 | 有，可多關 |
| 學生 | 讀教材卡在某個重點時，AI 助手依他的問題產生 30–100 秒短片、小 PPT，或在心智圖上標出問題位置 | 沒有，當場生成 |

現階段實際操作的人是專案作者（工程師）和 Claude，一起把流程與元件做穩。

## 流程：只有一條

1. 教材進來
2. 整理成教材架構、抓重點
3. 拆成小單元（一個單元一個重點）
4. 排問題鏈（每個單元回答上一個留下的問題）
5. 每個單元寫分鏡骨架（每頁一句話＋要呈現什麼），先審順序
6. 寫旁白，全部走同一套旁白規則（`video_engine/prompts/narration_style_tw.md`）
7. **文本定稿後才選風格**：一份教材用一種風格（手帳、黑板，之後白板）
8. 從那個風格的元件裡挑，填文字與動作
9. 配音
10. 渲染

第 1–6 步跟風格無關，只做一次。風格是輸出方式，不是另一條流程。

### 幾個定下來的原則

- **不是兩條線。** 沒有「手帳流程」「黑板流程」。黑板是加進同一條線的一種風格，吃同一份分鏡與旁白，不另開寫稿入口。
- **參考來的東西改成自己的。** 外部風格（例如黑板的來源）只當參考，做成自己的元件與格式，不為了相容原本的格式而保留它。
- **舊影片不回頭改。** printf 片、圖示展示片是優化過程的紀錄。
- **元件共用、風格各自。** 分鏡怎麼寫是共用的，尺寸與畫法由各風格自己定。
- **風格畫不出來的東西**：先退成文字並記成缺口，用缺口決定下一個補什麼元件；不替單支片手寫畫面。

## 畫面原則

- 影片文字少、圖多，旁白負責解釋；講義 PPT 圖文搭配、自己看得懂。兩者不要長得一樣。
- 用版面說明畫面，不加多餘的說明字。
- 版面要穩：每頁只用固定幾種模板，圖區位置固定。
- 黑板只畫原理；程式碼放電腦畫面（VS Code 元件）。
- 元件要夠大，不留一堆空白。
- 旁白講意思，不念畫面上的符號。
