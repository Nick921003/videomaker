# b14 講稿草稿 v2（老師回饋：太快、畫面字多旁白少）

b13：20 句、97 秒。b14：28 句，預估 3 分半左右。

## 節奏怎麼改

- **先畫，再講。** 每一頁換過來之後，圖先畫完，旁白才開始講。講的時候用粉筆圈、畫底線、加箭頭，標出現在講到圖上哪裡，學生的眼睛才跟得上。頁面上方那行字幕還是跟著旁白一個字一個字寫出來。
- **兩句同一頁**：同一張圖分兩步。先畫第一步，講第一句；再畫第二步，講第二句。
- **電腦畫面**：游標先做動作（點下去、打字），畫面變完了，旁白再說剛剛做了什麼，講完停一下才做下一步。
- **一頁只畫一張圖**；畫面上出現的字，旁白都要講到。
- **換頁時間不變**：板擦 1.8 秒、平移 1.2 秒、進出電腦畫面 2.5 秒。
- **語速不調慢**：王老師的聲音放慢會變得不自然，所以「不要那麼快」靠「先畫後講」和每步之間的停頓來做到。

句子之間加了轉接的話（標 ↪），像老師上課那樣一步一步帶過去，不會一句跳到下一句。

## 症狀（黑板 2 頁）

第 1 頁：程式卡片
1. 我們先用 Code Runner 跑這支程式。
2. 這支程式會先印出「請輸入一個整數」，然後等你打一個數字。

第 2 頁：輸出面板
3. 可是你看，按下去之後，「請輸入一個整數」並沒有跑出來。
4. 輸出面板只有一行 Running，程式就一直卡在這邊。

## 原因（黑板 4 頁）

第 3 頁：緩衝區
5. ↪ 奇怪，程式明明有寫 printf，為什麼字沒有出來呢？
6. 這是因為 printf 印的字不會馬上出現，會先放進一個叫緩衝區的地方。

第 4 頁：終端機
7. ↪ 那字什麼時候才會出來？要看程式是在哪裡跑。
8. 如果是在終端機跑，字會馬上印出來。

第 5 頁：輸出面板（同一張圖分兩步）
9. 可是 Code Runner 預設是在輸出面板跑。
10. 在輸出面板，字就會一直卡在緩衝區，要等程式結束才一起出來。

第 6 頁：唯讀（同一張圖分兩步）
11. ↪ 而且還有一個問題，輸出面板只能看，不能打字。
12. 所以 scanf 一直等不到你輸入，程式就卡住了。

## 網路上的解法：加 fflush（黑板 2 頁）

第 7 頁：fflush（同一張圖分兩步）
13. ↪ 那要怎麼辦呢？網路上有一個解法，在 printf 後面加一行 fflush。
14. fflush 會把緩衝區裡的字馬上推出來。

第 8 頁：還缺什麼
15. 可是這樣還不夠，因為輸出面板還是不能打字。我們直接到電腦上試一次。

## 在電腦上做一次（電腦畫面）

16. 加了 fflush 之後，你看，提示字出來了。
17. 可是當我們要打字的時候，下面就說這裡是唯讀的。
18. ↪ 這時候先別急著改設定，先按編輯器右上角這個紅色方塊，把卡住的程式停掉。
19. ↪ 為什麼要先停？因為沒停掉的話，程式會一直佔著執行檔，下次編譯會失敗。
20. ↪ 停掉之後，我們就讓 Code Runner 改到終端機跑。
21. 先點左下角的齒輪，選設定。
22. 然後在上面的搜尋框打 run in terminal。
23. 找到 Code Runner 的 Run In Terminal，把它打勾。
24. ↪ 設定好了，我們換回沒加 fflush 的那支，再跑一次。
25. 這次是在下面的終端機跑，提示字馬上就出來了。
26. 輸入 5，按下 Enter，結果就出來了。

## 在終端機卡住怎麼停（黑板 1 頁，同一張圖分兩步）

27. ↪ 那如果換成在終端機裡卡住，要怎麼停呢？
28. 先點一下終端機，再按 Ctrl 加 C，程式就會停下來。

## 結語與複習頁（不變）

所以記得，程式要輸入東西，就要在終端機跑。
（複習頁）下次執行程式，如果 printf 沒有出來，就照這個順序檢查一遍。
