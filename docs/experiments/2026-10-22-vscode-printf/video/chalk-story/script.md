title: printf 沒出來？
subtitle: 按 Run Code 卡住，改一個設定就好

## symptom | 症狀：按下去就卡住
這是一份作業：讓你輸入成績，再把成績印出來。
程式寫好了，我們按右上角這個三角形，用 Code Runner 跑跑看。
結果什麼都沒有出來，輸出面板只有一行 Running，程式就停在這裡。
很多同學第一次用 VS Code 跑程式，都卡在這裡。
我們畫到黑板上看。照順序，程式應該先印出「請輸入成績」，再停下來等你打字。
可是右邊的輸出面板，提示字該出現的地方是空的，程式就一直停在這裡等。
> 先印提示字，再等你輸入
> 提示字沒出來，程式停住

## cause | printf 為什麼沒出來
奇怪，程式明明有寫 printf，為什麼提示字沒有出來呢？
先看程式是在哪裡跑。Code Runner 沒改設定的話，是在輸出面板跑。
然後，printf 要印的字不會直接到畫面上，會先放進一個暫存的地方，這叫緩衝區。
在輸出面板跑的時候，緩衝區的字不會馬上印出來。
要等整支程式跑完，這些字才會一起出來。
同樣這支程式，如果改在右邊的終端機跑，printf 一執行，字就會顯示出來。
> Code Runner 預設在輸出面板跑
> printf 的字先進緩衝區
> 輸出面板：程式結束才一起出來
> 終端機：直接顯示

## fflush | 網路上的解法：加 fflush
那要怎麼辦呢？網路上有一個解法，在 printf 後面加一行 fflush。
fflush 會把緩衝區裡的字推出去，不用等程式結束。
所以右邊這行提示字就出來了。
> fflush：把緩衝區的字推出來
> 提示字出來了

## scanf | 可是 scanf 還是不行
可是程式還有下一行 scanf，要等你打數字。
問題是，輸出面板是唯讀的，只能看、不能打字。
你從鍵盤打的數字送不進去，scanf 就一直等。
一開始程式停在那裡不動，就是因為 scanf 在等你輸入。
這件事 fflush 幫不上忙，要讓程式改在終端機跑。
我們直接到電腦上做一次。
> 輸出面板只能看、不能打字
> scanf 等不到輸入 → 卡住
> fflush 幫不上忙

## screen | 改在終端機跑
先看加了 fflush 的這支，按三角形跑，提示字出來了。
可是想在輸出面板打數字，下面就說這裡是唯讀的。
唯讀就是只能看，所以數字打不進去。
先別急著改設定，先按右上角這個紅色方塊，把卡住的程式停掉。
為什麼要先停？因為程式卡著，會一直佔著執行檔。
沒停掉的話，下次編譯會失敗，出現 Permission denied。
停掉之後，我們讓 Code Runner 改到終端機跑。
終端機就是下面這個可以打字的視窗。
先點左下角的齒輪，選設定。
在上面的搜尋框打 run in terminal。
找到 Code Runner 的 Run In Terminal，把它打勾。
這樣 Code Runner 以後都會在終端機跑。
我們換回沒加 fflush 的那支，再跑一次。
這次在終端機跑，提示字直接出來了。
輸入 85，按 Enter，結果就出來了。
> 提示字出來了，還是不能輸入
> 按紅色方塊停掉卡住的程式
> 不停：下次編譯 Permission denied
> 改在終端機跑
> 齒輪 → 設定
> 搜尋 run in terminal
> 打勾
> 換回 score.c，在終端機跑
> 輸入 85：可以輸入了

## stop | 在終端機卡住怎麼停
那如果在終端機裡卡住，要怎麼停呢？
左邊這個終端機，程式一樣停在等輸入。
先點一下終端機，讓它接收你按的鍵。
再按右邊這兩個鍵，Ctrl 加 C，程式就停了。
> 點終端機 → Ctrl + C

## end
emphasis: 終端機
