## 一、症狀：按下去就卡住

### 頁 1｜置中：程式卡（四行程式碼＋右上角三角形）
1. 我們先來看這支程式，一共四行。
2. 第一行開一個變數 n，用來裝你打的數字。
3. 重點是中間這兩行：printf 先印出「請輸入一個整數」，scanf 再等你打數字。
4. 最後一行把你打的數字印出來。
5. 我們按右上角這個三角形，用 Code Runner 跑跑看。

### 頁 2｜置中：輸出面板（提示字被劃掉、Running、沙漏）
6. 照順序，應該先看到「請輸入一個整數」，才輪到你打字。
7. 可是你看，按下去之後，這行字沒有跑出來。
8. 輸出面板只有一行 Running，沙漏一直轉。
9. 程式卡在這邊，不會結束。

## 二、原因：字卡在緩衝區

### 頁 3｜雙欄：左 printf → 右 緩衝區格子
10. 奇怪，程式明明有寫 printf，為什麼字沒有出來呢？
11. 因為 printf 印的字不會馬上出現。
12. 它會先一個一個落進這排格子，這叫緩衝區。

### 頁 4｜雙欄：左 緩衝區 → 右 兩條路（上：終端機，下：問號）
13. 那字什麼時候才會出來？要看程式在哪裡跑。
14. 緩衝區分出兩條路，上面這條是終端機。
15. 在終端機跑，字會馬上印出來。
16. 下面這條先打個問號。

### 頁 5｜雙欄：左 緩衝區（堆著字）→ 右 輸出面板，中間一道牆，箭頭上寫「預設」
17. 這個問號就是輸出面板。
18. Code Runner 預設就在這裡跑，所以箭頭上寫「預設」。
19. 在輸出面板跑，中間像隔了一道牆，字卡在緩衝區出不去。
20. 要等程式跑完，牆拿掉，字才一起出來。

### 頁 6｜置中：上鎖的輸出面板，下面鍵盤，箭頭打不進去
21. 而且輸出面板只能看，不能打字，所以畫了一個鎖。
22. 你從鍵盤打的數字送不進去。
23. 所以 scanf 等不到輸入，程式就不會結束。
24. 程式不結束，提示字就一直出不來。

## 三、網路上的解法：加 fflush

### 頁 7｜雙欄：左 程式卡（printf 下面多一行 fflush，卡上照寫 fflush(stdout)，旁白只念 fflush）→ 右 緩衝區把字推出去
25. 那要怎麼辦呢？網路上有一個解法，像左邊這樣，在 printf 後面加一行 fflush。
26. fflush 會把緩衝區裡的字馬上推出去。
27. 所以右邊這些字就出來了。

### 頁 8｜置中：輸出面板，提示字出來了，可是鎖還在
28. 可是字出來了，輸出面板還是鎖著，還是不能打字。
29. 我們到電腦上試一次。

## 四、在電腦上做一次（VS Code 畫面，不套模板）

30. 加了 fflush 再跑一次，提示字出來了。
31. 可是想在輸出面板打數字，下面就說這裡是唯讀的。
32. 唯讀就是只能看，所以數字打不進去。
33. 先別急著改設定，先按右上角這個紅色方塊，把卡住的程式停掉。
34. 為什麼要先停？因為程式卡著，會一直佔著執行檔。
35. 沒停掉的話，下次編譯會失敗，出現 Permission denied。
36. 停掉之後，我們讓 Code Runner 改到終端機跑。
37. 終端機就是下面這個可以打字的視窗。
38. 先點左下角的齒輪，選設定。
39. 在上面的搜尋框打 run in terminal。
40. 找到 Code Runner 的 Run In Terminal，把它打勾。
41. 這樣 Code Runner 以後都會在終端機跑。
42. 我們換回沒加 fflush 的那支，再跑一次。
43. 這次在終端機跑，提示字馬上出來了。
44. 輸入 5，按 Enter，結果就出來了。

## 五、在終端機卡住怎麼停

### 頁 9｜雙欄：左 卡住的終端機（沙漏）→ 右 Ctrl + C 兩個鍵
45. 那如果在終端機裡卡住，要怎麼停呢？
46. 左邊這個終端機，程式一樣卡在等輸入。
47. 先點一下終端機，讓它接收你按的鍵。
48. 再按右邊這兩個鍵，Ctrl 加 C，程式就停了。

## 結尾

49. 所以記得，程式要輸入東西，就要在終端機跑。
