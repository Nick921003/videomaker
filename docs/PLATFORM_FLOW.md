# 多元教材平台：設計流程與架構

整理日期：2026-10-14。來源是與使用者逐題討論的結果；細部規格另見 `docs/superpowers/specs/`。

## 1. 最終形態

教材放上平台。學生讀教材卡在某個重點，AI 助手問要不要換一種呈現方式（例如影片）→ 先到素材庫找對應這個重點的成品 → 沒有就當場生成，對話框顯示「生成中」。這條按需生成流程就是自動化，過程中沒有人工檢查。

## 2. 教材統一化：教材架構

不是把同一份文字硬塞進每種形式，而是把寫給人看的 Markdown 整理成寫給 AI 用的「教材架構」，任何成品都從架構直接產生。

```
教材 Markdown（寫給人看）
        ↓ AI 整理一次（付費）
教材架構（寫給 AI 用）
  每個重點 = 問題、講解文字、示範資料（追蹤表每一圈的值、對照的兩段程式、流程的每一步）
        ↓ 之後都是純轉換，不再呼叫 AI
 ├─ 心智圖：取層次
 ├─ 講義：靜態圖 + 短文字
 ├─ 影片：動態解釋 + 旁白
 └─ 未來的測驗、閃卡……
```

**架構只放「教什麼」，不放「怎麼畫」。** 同一份追蹤表數值，講義畫成靜態表格讓學生一格一格看；影片可以讓數值在格子裡跳動、條件燈號一亮一滅，或換成完全不同的比喻動畫。講義與影片內容一致但呈現不同，避免兩者太像。

## 3. 各成品定位

| 成品 | 定位 |
| --- | --- |
| 講義（PPT） | 圖文搭配，學生自己看得懂「原來架構是這樣」；不可全文字，也不是全圖沒有解釋 |
| 影片 | 用動態方式解釋：文字少、圖多，旁白負責解釋圖 |
| 心智圖 | 把教材圖示化呈現觀念之間的連貫，點一下長一層 |

## 4. 心智圖：點一下長一層

```
蘋果樹（主題）
 ├─ 蘋果（重點）─點→ ├─ 蘋果的定義（框裡直接是內容）
 │                   │     ─點→ ├─ 例子 ─點→ 例子內容
 │                   │          └─ 常見錯誤 ─點→ 錯誤內容
 │                   └─ 料理（延伸，用主題命名，教材有提到才長）
 │                         ─點→ 料理的內容
 ├─ 樹幹（重點）……
 └─ 樹葉（重點）……
```

定義與例子最重要；延伸只有教材有提到才做。

## 5. 產生時機：預先做好基本架構，學生問到再長

```
教材上架 → 先做好基本架構（重點 A1、A2、A3……）     便宜，涵蓋大部分情況
                ↓
學生提問 → 先比對：問題落在哪個重點？
   ├─ 落在既有重點（就是 A）→ 直接用現成的講義、影片
   └─ 是 A 衍生出來的 B → 當場產生「衍生重點 B」，掛在 A 底下
          → 跑同樣的自動檢查（出處、gcc、GPT）
          → 產生學生要的成品
          → 存回素材庫，下一個問 B 的學生直接用
```

基本架構替衍生問題提供脈絡（知道學生從哪裡卡住），架構也隨學生提問長大。

## 6. 檢查原則

每一關都要能自動檢查，人工確認只是可選的額外一層。

| 關卡 | 怎麼自動檢查 |
| --- | --- |
| 重點清單 | 出處必須對到教材原文片段；欄位與字數上限由驗證器擋 |
| 學習目標（教材沒寫、由 AI 推論） | GPT 交叉審查 |
| 示範資料 | 重點確認後才產生；追蹤表等數值用 gcc 實際編譯執行核對（限時、無網路） |
| 教材外的問題 | 先找教材依據；找不到才補充，標示「教材外補充」、GPT 審查加嚴，存成補充而非正式重點，之後老師可看哪些問題常被問 |
