### 從現在到完成的順序

1. **新版鏈路已驗：** 8901 上以公開合成教材完成「上傳→AI 整理→簡報計畫→生成→逐頁預覽→核可→PPTX 下載」，產出七頁、可編輯 PPTX 與相同來源 revision；模型 token 限制由單元測試驗證。
2. **修來源忠實度：** 將 Deck v1 的單一頁面引文提升為逐項依據，或在升版前設置人工審核閘；對無原文支持的比較／迷思／數值明確拒絕。回歸舊 Deck v1 讀取。
3. **完成投影片可讀性：** PPTX 首輪最低字級與過長拒絕已實作；接著用四類教材檢查線上預覽 375、768、1024、1440 px 與匯出 PDF 每頁。
4. **完成四種內容驗收：** 以公開合成教材做真實模型生成，記錄逐頁支持度、可讀性、操作與失敗案例。檢查新版 AI 整理是否扭曲來源。
5. **開直接 PPTX 入口：** 同一 Deck 工作只生成一次，線上預覽與可編輯檔共用一份內容；完成 API 和 UI 全流程測試。
6. **實際 PowerPoint 編輯與文件收尾：** 在可用的 PowerPoint 環境驗證編修；更新 `NEXT_STEPS.md` 和產品規格。以上未完成前不標記「PPT 完成」。

**驗收定義：** 學生可從教材取得可讀、可核對來源的簡報；教師可取得並編修 PPTX；四類合成教材的關鍵主張均有依據、無裁字，且最新版全流程、回歸測試與實際編修檢查有紀錄。使用者自己的教材仍需由使用者最後確認是否適合該課程。

## 目標與使用者

學生在 BridgeAI 閱讀一段已發布教材但看不懂時，能選「簡報版」逐頁理解核心概念、關係、例子與易錯處。測試站現階段以上傳教材代替 BridgeAI topic。可編輯 PPTX 是同一份內容的匯出形式，主要供教師或開發者修改、發布；線上預覽是學生主要閱讀形式。

## 已完成的基線

- 教材上傳、簡報計畫、生成進度、逐頁線上預覽、來源引文、核可與可編輯 PPTX 下載已接通。
- Deck v1 限定 3–12 頁，只有 bullets、steps、compare、code 四種內容版型。每頁一個主區塊、原文引用與講者備忘稿；PPTX 保留原生文字與圖形。

- 直接選 `pptx.editable_deck.v1` 仍為 planned；目前須先選線上簡報，核可後下載 PPTX。

## 品質缺口與設計依據

檢視既有六頁雨水回收樣本，五頁主要使用類似清單卡片，兩頁步驟頁只是直列文字；學生較難一眼看出「路線」「操作順序」與「常見誤解」的不同任務。現有簡報可讀，但頁面角色的視覺差異不足。

使用本機 `soil-teaching-deck` 技能的概念定位、三段理解節奏、每頁一個任務、認知編修與逐頁 QA 作為教學原則；現有系統是自動生成器，因此將技能規則轉為可驗證的內容與版面約束，不直接照搬一次性人工製作或每頁必須生圖的流程。

參照 [python-pptx 官方文件](https://python-pptx.readthedocs.io/en/latest/user/notes.html) 的可編輯文字、形狀與備忘稿能力，以及 [Presenton 原始專案](https://github.com/presenton/presenton) 的「文件輸入→預覽→可編輯 PPTX」流程。現有 `python-pptx` 已能滿足第一輪，先不增加 PptxGenJS 或影像生成依賴。

## 建議本輪交付：內容與版面品質

1. **教學內容：** 明確要求核心問題、最小事實包、頁面理解任務與最後的自我檢查。學生必須能從可見投影片讀懂主旨，備忘稿只放延伸內容。標題要表明學生學到什麼；迷思頁只在教材有根據時生成。Deck v1 沒有明確的學習目標、自我檢查與逐項引文欄位，因此這些要求暫屬生成指令與人工審核，不宣稱可由伺服器自動保證。若要自動驗證，先設計 Deck v2 並保留 v1 讀取相容。
2. **線上頁面：** 利用現有 role/layout 資訊做不同頁型：問題引入頁、概念分組頁、編號步驟頁、真正對照的比較頁、總結與檢核頁。Deck v1 的 `steps` 只代表順序；沒有明確線性流程標記時，不畫暗示因果或分支的連線。小螢幕保持單欄與閱讀順序，支援鍵盤切頁。
3. **PPTX：** 與線上預覽使用同一 Deck 內容及相同的頁面語意。線上頁面顯示延伸解說與可展開的來源；PPTX 在備忘稿中保存延伸解說及完整原文引文，並在教師編輯時可找到。文字與形狀都可編輯。不得以無下限的自動縮字掩蓋溢出；設定最低可讀字級，超界時改版、拆頁或拒絕輸出，並以實際 PowerPoint 編輯驗收。
4. **驗證：** 至少用概念、程式碼、比較（無迷思依據）和較長流程四份公開合成教材，逐頁比對每項標題、要點、關係和 notes 是否受教材支持。每頁的引文定位只能作審核線索，不能當成整頁真實性證明。檢查是否有引起動機、逐步解釋、可見的總結／自我檢查，無根據迷思為失敗。PPTX 重新開檔查文字、形狀與 notes；轉 PDF 逐頁目視查裁字、重疊、對比；在可用時用 Microsoft PowerPoint 實際編輯。瀏覽器在 375／768／1024／1440 px 檢查可讀性和操作。回歸影片與心智圖入口。

## 後續兩個獨立決策

- **直接選可編輯 PPTX：** 若使用者要此入口，讓它重用 `slides.lesson_deck.v1` 的生成與審核流程，同一份已核可 Deck 匯出，不增加第二次模型生成。需完成計畫、catalog、API 與前端全流程測試後才標為 available。
- **圖片／幾何圖：** 視學生試用與教材類型再擴充版本化 Deck 契約；AI 插畫要有一致風格、成本預估、來源與可及性驗收。此項不得阻擋文字／原生形狀版本落地。

## 邊界

- 不取用使用者先前上傳的私有教材呼叫外部模型；真實模型驗證使用公開合成教材。
- 不覆蓋影片優化對話的工作；本輪只處理簡報生成與輸出。
- 目前 8900 測試服務中的 job／artifact 在記憶體，不能為部署新程式直接重啟而丟失使用者心智圖。測試新程式應使用隔離流程或先保存並恢復狀態。
