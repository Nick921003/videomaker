# 獨立多格式教材工作台：八步整體計畫

日期：2026-10-08（Asia/Taipei）

> 2026-10-09 範圍更新：使用者要求先聚焦影片、簡報與心智圖的自動化和品質，不拓展新產物。當前進度與下一階段依 [`2026-10-09-three-output-quality-roadmap.md`](2026-10-09-three-output-quality-roadmap.md)；本文件保留八步歷史，Podcast、海報、漫畫及平台串接暫緩。

狀態：第一、二步技術驗收完成；第三步已接入共同資料並補上AGY審查修正。第四步使用者視覺與內容驗收未通過，需補AI教學規劃、元件動畫接入與新版展示，保持未完成。第五至八步待接續。

## 目標與範圍

專案獨立讀取各種教材來源，保存可追溯的共用教材資料，由 Gemini 生成指定教材。部署與日常操作不依賴 Codex、聊天框或本機外掛快取目錄。

使用者確認的產出只有以下五類；講義、測驗、學習卡不列入本輪主要範圍。

| 類型 | 交付內容 |
| --- | --- |
| 簡報 | 線上逐頁預覽、原生可編輯 PPTX |
| 心智圖 | 概念與關係、縮放預覽、SVG 下載 |
| 影片 | 各重點短影片；長影片由多支重點影片串接並補上銜接 |
| Podcast | 單元講解或師生問答、音訊與逐字稿 |
| 圖片式教材 | 海報呈現重點；漫畫呈現情境、步驟或迷思 |

候選輸入：PDF、PPTX、DOCX、XLSX、CSV、Markdown、TXT、圖片。舊格式 PPT／DOC／XLS 另評估轉檔與限制，不宣稱已支援。

## 共用流程與約束

來源檔案 → 格式解析 → 文字／表格／圖片與來源位置 → Gemini 整理與內容檢查 → 保存共用教材資料 → 指定產物生成 → 排版／繪圖／配音／合成 → 預覽與下載。

- 新版 `workbench/` 是主線；保留既有影片、簡報、心智圖實作，先接入、再補強，不整套重寫。
- 新版內容生成沿用目前預設 `google:gemini-3.8-flash`。模型覆蓋設定需可追蹤；語音、圖像生成另行配置，不能視為同一模型的能力。
- 參考文件外掛的流程及可重用工具；確認相依與使用條件後才採用。不能把 SKILL.md 或外掛快取當作後端函式庫。
- 共用資料逐步以 JSON 保存結構，Markdown 提供閱讀與舊流程相容；保留原檔、原始抽取、整理結果與來源定位。
- 重用同一教材版本的整理結果及已完成產物；教材改版、模型／提示／輸出契約改變時需判斷快取是否失效。
- 不猜看不清的數值、圖表或程式碼；疑點須保存並顯示。引文可定位只證明來源存在，不能代替內容正確性驗收。
- 用量分開記錄教材整理、產物內容生成、語音與圖像；重試與失敗的已回報用量亦須保留。
- 各步驗收後更新本文件。發現跨步依賴時先記錄；只有阻止當步安全運作的問題才提前修復。
- 第一步不增加第三方依賴、不改舊工作台；第二步若需要新依賴，先列明理由、部署方式及現有依賴的替代可能性。
- 不覆蓋既有未提交工作、不自行提交或推送。測試使用隔離暫存資料，避免改寫真實單元。
- 自動驗收不呼叫付費模型、TTS 或外部網路；真實生成驗收須有明確授權，費用估算與实际回報分開。

## 八步順序與完成標準

| 步驟 | 工作 | 完成標準 |
| --- | --- | --- |
| 1 | 穩定新版工作台 | 無付費測試通過；非 mock HTTP 流程可驗；保存、重啟、失敗重試與前端主要入口有證據；未驗項目明示 |
| 2 | 多格式讀取與共用教材資料 | 來源格式有明確支援表；結構與来源保存；圖像、表格、疑點處理可驗；不支援檔案有清楚錯誤 |
| 3 | 接入現有簡報、心智圖、影片 | 三種產物使用同一份已核對教材版本；可對回來源；不重複整理與計費 |
| 4 | 優化 PPT 與心智圖製作 | 教學內容、版型選擇、關係表達與可讀性有改善證據；PPTX 保留原生可編輯元素；HTML／PPTX／SVG 實際產物驗收 |
| 5 | 重點短影片與串接長影片 | 可選片段與順序；處理銜接、字幕及音訊；重用片段；驗證最終檔案與播放 |
| 6 | Podcast | 單人講解及師生問答可生成；音訊與逐字稿一致；聲線、漏念與重配可驗 |
| 7 | 海報與漫畫 | 先海報後漫畫；教學文字由程式排版；來源忠實、閱讀順序與角色一致性可驗 |
| 8 | 獨立部署與整體驗收 | 固定依賴與設定；乾淨環境可啟動；來源到五類產物可操作；不需要聊天框；限制有文件 |

BridgeAI 正式接入排在上述流程穩定之後；本計畫不宣稱既有帳號、課程權限或多人服務已完成。

## 第四步：優化 PPT 與心智圖製作

第三步負責接通共用教材資料；第四步專門改善教學內容與產物品質，不能把「能生成檔案」視為優化完成。本步仍沿用 Gemini 內容生成與專案本機排版，正式運作不依賴聊天框。

### PPT 製作優化

- 先盤點既有 Deck 1.1、生成提示、內容契約、HTML 預覽與 PPTX 匯出，保留每頁可見 takeaway、講者備忘稿及來源引用。
- 依教材選擇要點、比較、流程、概念圖、程式碼等版型；避免每頁都變成密集條列或全頁圖片。
- 每頁聚焦一個教學主旨；必要解釋與範例放在學生能看到的位置，不只藏在備忘稿。
- 改善字級、資訊密度、換行、間距、圖文配置與視覺層級；超出可讀容量時分頁或明確拒絕，不靠無限制縮字塞入。
- PPTX 保留可編輯文字、圖形與連線；數值、術語、程式碼及必要表格資訊可對回教材。
- 驗證 HTML 預覽與 PPTX 的內容一致性，並檢查實際匯出檔的排版與編輯能力。

### 心智圖製作優化

- 先盤點既有樹狀契約、概念／關係生成與 SVG 繪製，確認哪些關係能準確表達。
- 改善概念挑選、層次、節點標籤及關係詞；避免把章節標題直接排成樹而沒有解釋概念。
- 區分上下位、组成、比較、流程與因果；不把不成立的關係硬塞成父子結構。若需跨節點關係，先提出契約與顯示方案，驗證後再擴充。
- 改善長文字換行、節點間距、連線與關係詞位置，避免重疊、裁切與標籤遮線。
- 保留來源定位、縮放、拖曳、符合視窗與下載；小螢幕也能有效操作。

### Codex／AGY 分工與驗收

- Codex：生成提示、資料契約、來源檢查、PPTX／SVG 產生器及後端測試。
- AGY：簡報／心智圖預覽、版面與操作整合、瀏覽器功能與尺寸驗收。
- 共同：以同一份固定資料比較修改前後的實際產物，分開評估內容與排版，避免把模型隨機差異當成版型改善。
- 範例至少涵蓋概念講解、操作流程、程式碼／比較及含表格／圖像的教材；資料由第二步共用格式提供。
- 自動檢查驗證來源、必要內容、越界、重疊、可編輯元素與格式契約；使用者確認教學適切性及視覺風格。
- 沿用既有 fixture 完成免費回歸；真實模型生成另按已授權範圍驗收，記錄成本與未驗限制。
- 交付優化前後樣本、程式變更、適用測試結果與验收紀錄；本步開始前再依前兩步資料契約展開精確檔案範圍。
