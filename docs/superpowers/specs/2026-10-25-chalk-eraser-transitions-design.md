# 黑板版換頁：板擦擦掉＋直線平移

日期：2026-10-25　狀態：使用者已同意方向，待樣片確認

## 為什麼

b10 換頁是「講完停 1 秒 → 鏡頭拉遠、轉角度、推近」，2.2 秒一次，全片 7 次。b11 把它壓到 0.5 秒，結果更像在跳：右邊剛寫完，畫面又往右甩，還帶晃。使用者的手帳版換頁是直線滑過去，不晃，看起來順得多。2026-10-23 使用者也說過「鏡頭一直往右會疲勞」「換頁不一定要移鏡」。

## 換頁分三層

| 換的是什麼 | 換法 |
| --- | --- |
| 一支片裡的粉筆頁（含換段） | **板擦擦掉**：鏡頭不動，板擦掃過整頁，新的一頁寫在同一個位置 |
| 進出電腦畫面、到報頭、到複習頁 | **直線平移**：只平移，不拉遠、不轉角度 |
| 換章（一支片接下一支片，合成重點片時） | 原本的晃動鏡頭。本片用不到，`travel` 保留 `sway` 開關 |

「段」＝ story.json 的 chapters（問題、原因、解法……）。換段時板擦連段名徽章和邊框一起擦，再寫上新的；同一段內換頁只擦內容，徽章和邊框留著。

## 版面

黑板只排一列：`[複習頁][報頭][粉筆區][電腦畫面…]`。沒有報頭或複習頁就不排那一格。

- **粉筆區**：所有粉筆頁疊在同一格。每一段一個「框面板」（邊框＋徽章），每一張粉筆頁一個「內容面板」，全部疊在同一個位置。
- **電腦畫面**：每段電腦畫面一格，排在粉筆區右邊。整段只有電腦畫面的段，框面板放在那一格。
- 時間順序：粉筆區 → 電腦畫面（往右）→ 回粉筆區（往左）→ 報頭（往左）→ 複習頁（往左）。全部是同一列上的水平移動。

beats.js 只透過 `api.slot / area / screen` 拿面板座標，所以每頁改成自己的面板、x 從 0 起算，beats 不用改。

## 擦掉

每張粉筆頁 A，找時間上下一張粉筆頁 B：

- **A、B 之間鏡頭沒離開粉筆區**：A 最後一句講完 0.1 秒後，板擦花 0.9 秒掃過整頁（kit 的 `X`，三條來回），A 的內容面板上所有東西被掃到就淡掉。B 跟 A 不同段時，A 那一段的框面板同時擦掉。
- **中間去過電腦畫面**：鏡頭不在粉筆區時瞬間清掉（觀眾看不到），回來時是乾淨的黑板。
- 最後一張粉筆頁不擦，直接平移到報頭。

擦的對象在所有東西都畫好之後（beats、標題、徽章都建完）才收集：內容面板的 svg 筆畫與每行粉筆字。

## 時間

| 換法 | 句間空白 | 組成 |
| --- | --- | --- |
| 板擦 | 1.8 秒 | 講完 0.1 秒 ＋ 擦 1.5 秒 ＋ 0.2 秒後開口（b12 擦 0.9 秒，使用者嫌像趕火車） |
| 平移 | 1.2 秒 | 講完 0.2 秒出發 ＋ 平移 0.9 秒 ＋ 到位 0.1 秒後開口 |
| 進電腦畫面 | 2.5 秒 | 0.2 ＋ 平移 0.9 ＋ 畫螢幕框與推近 1.4 |

`f5_story.py`：`ERASE_GAP = 1.8`（粉筆頁換粉筆頁）、`TRAVEL_GAP = 1.2`（平移）、`SCREEN_GAP = 2.5`。b11 的「錨點提前 0.25 秒」與「每頁最後一句的句尾提早 0.3 秒收筆」保留。
