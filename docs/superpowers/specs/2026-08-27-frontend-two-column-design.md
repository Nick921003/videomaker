# 前端雙欄改版 — 設計文件

**日期**：2026-08-27
**範圍**：只動 `web/index.html`。後端、API、SSE 契約一律不碰。

---

## 1. 現況

單欄、由上往下：頂部一條進度區（進度條 + 八個階段卡），下面是五個互斥的「畫面」，同一時間只顯示一個：

| 畫面 | 內容 |
| --- | --- |
| `screen-upload` | 拖放區、預期秒數、開始按鈕 |
| `screen-running` | 只有一行「進行中：階段名」 |
| `screen-review` | 倒數、講稿 textarea（每頁一組，含投影片預覽圖） |
| `screen-done` | 影片播放器、下載、製作下一部 |
| `screen-failed` | 失敗原因、返回 |

問題：進度區在最上面，審稿時要往下捲才看得到講稿，看不到進度；`screen-running` 整片空白，八個階段卡在上面卻沒被當成主角。

## 2. 要做什麼

改成**持久的雙欄外殼**，兩欄同時存在、互不遮蔽：

```
┌────────────────────────────┬──────────────────┐
│ 左欄：工作區                │ 右欄：進度        │
│                            │                  │
│  · 拖放教材                 │  總進度條 + 百分比 │
│  · 投影片預覽               │  八個階段卡（直排）│
│  · 逐字稿編輯               │  倒數計時（審稿時）│
│  · 影片播放                 │  失敗原因（失敗時）│
│                            │                  │
│  （依階段切換內容）          │  （全程可見）      │
└────────────────────────────┴──────────────────┘
```

- **右欄全程可見**，不隨階段消失。使用者任何時候都看得到跑到哪一階段、還剩多少。
- **左欄依階段切換內容**，沿用現有的五個 `screen-*` 區塊與 `showScreen()` 機制。
- 寬度比例約 **左 2 : 右 1**，右欄設下限（約 300px）避免階段卡被壓扁。

## 2.5 真正要解決的問題：不要再捲整頁

使用者的原話是「目前前端我要一直往下滑很麻煩」。**分成兩欄只是手段，目標是消掉整頁捲動。**

最兇的是審稿頁：五張投影片預覽圖（每張佔滿欄寬）+ 十六個逐字稿框，疊成一條又長又窄的柱子。往下捲改稿的時候，倒數計時和進度全部捲出畫面——正是最需要看到倒數的時候看不到。

所以外殼要這樣做：

1. **整頁不捲。** 外殼高度 `100dvh`，`body` 不產生垂直捲軸。
2. **只有左欄自己捲。** 左欄是獨立的捲動容器（`overflow-y: auto`），右欄釘住不動。改稿捲到第五頁時，倒數與八個階段卡仍然在畫面上。
3. **審稿頁的高度要砍掉。** 現在是「投影片圖佔滿欄寬 → 底下接該頁的逐字稿框」，一頁就吃掉一個半螢幕。改成**投影片與該頁逐字稿左右並排**（投影片約佔左欄的 40%，逐字稿佔 60%），一頁壓進一個螢幕高度以內。頁與頁之間仍然往下排，但總高度砍掉一半以上。
4. **右欄本身也不該需要捲。** 八個階段卡直排 + 進度條 + 倒數，要在 900px 高的視窗裡放得完；放不下就把階段卡改成兩欄小格。

驗收就用這句話：**在 1920×1080 的視窗裡，審稿階段看得到倒數、看得到目前投影片、也改得到那一頁的逐字稿，中間不需要捲動。**

## 3. 硬性約束

1. **45 個 `id` 一個都不准掉、不准改名。** JS 全靠 `getElementById` 找元素，掉一個就是靜默失效——按鈕沒反應、進度不動，而且不會有任何錯誤訊息。這是這次最容易出事的地方。
2. **`<script>` 區塊的邏輯不准改。** 這次是**重排 HTML 與 CSS**，不是改行為。SSE 訂閱、倒數、審稿送出、下載、重置全部原樣保留。唯一允許的 JS 改動是第 4 節的模式選擇器所需的 `FormData` 欄位。
3. **暖色票一個都不准換**：`#F4EDE2`（頁底）、`#FBF7F0`（卡片）、`#DFD2BF`（卡片邊）、`#3B322A`（主文字）、`#4B4238`（次文字）、`#B85C38`（強調）、`#A0673F`（完成）、`#EFE6D8`（編輯區底）、`#DCCDB6`（編輯區邊）、`#F2D9A0`（警示底）。不准出現 `#FFF`／`#000`。
4. **不准引入 CDN、框架、建置步驟。** 單一 HTML 檔，內嵌 CSS 與 JS，`serve.py` 直接吐這個檔。
5. **窄螢幕要退回單欄。** 約 900px 以下改成上下堆疊，右欄（進度）排在**上面**——手機上先看到進度比先看到拖放區合理。
6. 投影片預覽圖已經有了（審稿時每頁一張，走 `GET /jobs/N/slide/<slide_id>`）。**維持現狀，不要改它的載入方式。**

## 4. 順便加：投影片版面模式選擇器

上傳區除了現有的「預期影片長度（秒）」，加一組四選一（見 `2026-08-27-layout-mode-selector-design.md`）：

| 標籤 | 送出的值 | 預設 |
| --- | --- | --- |
| 隨機 | `random` | **是** |
| 自動 | `auto` | |
| 雙欄 | `split` | |
| 置中單欄 | `center` | |

送出時 `FormData` 多帶兩個欄位：

- `layout`：上列四個值之一
- `seed`：選 `random` 時**每次送出擲一個新的整數**（`Math.floor(Math.random() * 2 ** 31)`）；其餘模式送 `0`

這是**唯一**允許的 JS 行為改動。

## 5. 驗證

| 項目 | 方法 |
| --- | --- |
| id 完整性 | 改動前後各抓一次全部 `id="..."`，差集必須為空 |
| JS 邏輯未變 | 除了 `FormData` 那兩行，`<script>` 區塊的 diff 必須只有縮排 |
| 色票未變 | 改動後的檔案裡出現的色碼必須是第 3 條那十個的子集 |
| 無外部資源 | `grep -c "http://\|https://\|cdn\|<link"` 必須為 0 |
| 實際能跑 | 起 `serve.py`，四個畫面都要能顯示；不自行判定視覺好壞 |
| 視覺 | 交使用者確認 |
