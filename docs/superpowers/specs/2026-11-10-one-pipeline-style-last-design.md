# 一條流程：文本先定稿，再依風格排畫面

2026-11-10。依據 `docs/專案目標與使用者.md`。

## 為什麼做

現在有兩個寫稿入口：

- 手帳：`board/author.py` 從教材出發，LLM 一次產出旁白＋元件＋版面（`scene.json`）。
- 黑板：手寫 `storyboard.json`（`explainer/storyboard.py`），沒有任何提示詞；還反過來用 `storyboard_to_scene.py` 把黑板分鏡轉給手帳。

結果是黑板片的文本沒有規則管（圖示展示片的旁白很生硬），而且「挑元件」發生在不知道風格的時候。使用者要的是一條線：文本整理一次，定稿後才選風格，再從那個風格的元件裡挑。

## 目標

1. 寫稿拆成兩段：**文本段**（跟風格無關）與**排畫面段**（選完風格才跑）。
2. 黑板變成一種風格：吃排畫面段的產物，不再有手寫分鏡入口。
3. 每種風格有一份**能力表**（會畫哪些元件與動作、有哪些版面、一頁放幾樣），排畫面的提示詞與驗證都讀它。
4. 同一份定稿文本，配音只做一次，兩種風格都用。
5. 驗收成果：一份真教材 → 一份文本 → 選黑板出一支、選手帳出一支。使用者能分別看出「旁白寫法」和「挑元件」合不合要求，以及問題出在哪份提示詞。

## 不做

- 拆單元、排問題鏈的新程式。`plan` 那一步照舊（它的提示詞是「學生會問的問題」切法），之後另案處理。
- 新的粉筆皮膚（陣列格子、變數表等）。這次只讓缺口被記下來。
- AI 自動選風格。這次風格是指令的參數，由人指定。
- 白板、PPT、心智圖、包成技能。
- 回頭改舊影片（printf 片、圖示展示片）。

## 反目標（做出來也算失敗）

- 還是有兩個寫稿入口，或文本段的提示詞裡出現任何風格專屬的字眼（「紙上」「黑板」「鏡頭往下移」）。
- 排畫面段改了旁白的任何一個字。
- 風格不會畫的元件被悄悄換成別的畫法，沒有留紀錄。
- 換風格要重新配音。
- 為了相容黑板原本的手寫格式而保留它。

## 做法比較

| 做法 | 內容 | 取捨 |
|---|---|---|
| 一、寫稿拆兩段（**採用**，使用者 2026-11-10 選定） | 文本段產骨架與旁白；排畫面段拿定稿文本＋風格能力表挑元件 | 每小節多一次 LLM 呼叫、提示詞要拆；順序和使用者的流程一致，兩段的問題分得開 |
| 二、不拆，黑板直接吃現在的 `scene.json` | 提示詞幾乎不動 | 挑元件時不知道風格；目錄 15 種黑板只會 3 種，大量退成文字；看不出 LLM 會不會依風格挑 |
| 三、文本後只排一份畫面，各風格自己翻譯 | 不多一次 LLM 呼叫 | 每種元件在每種風格的替代規則都要寫成程式，規則多、效果難好 |

外部做法：Code2Video 也是先規劃分鏡再產畫面（見 `docs/參考紀錄.md`），但它讓 LLM 寫繪圖程式，和我們「只從目錄挑」的取捨相反，只當旁證。

## 設計

### 流程與指令

```
教材.md
  └─ author.py plan    → plan.json                      （現有，不動）
  └─ author.py script  → <id>.script.json ＋ review.md   （新：文本段）
        ── 人審骨架與旁白（老師端）；學生端自動通過 ──
  └─ 配音（F5，逐句，一次）
  └─ author.py stage --style <風格> → <id>.<風格>.scene.json   （新：排畫面段）
  └─ 該風格的出片程式
```

每個指令吃同一個輸出資料夾、只讀前一步的檔案、只寫自己的檔案。之後技能就是依序呼叫這幾個指令。

### 1. 文本段：`script.json`

一個小節一份。內容只有語意，**沒有元件型別、版面、座標**：

```json
{
  "version": 1, "id": "q1", "title": "片名", "question": "學生口吻的問題",
  "pages": [
    {"id": "p1", "title": "頁標題",
     "spine": "這頁要讓學生懂的一句話",
     "show": "這頁畫面要演出什麼（文字描述：主角是什麼、怎麼變化）",
     "kind": "concept | screen",
     "lines": [{"say": "字幕", "spoken": "（選填）唸法"}]}
  ],
  "end": {"say": "結語", "emphasis": "一句重點"},
  "recap": {"say": "複習頁旁白", "items": ["要點 | 說明"]}
}
```

- `kind` 只分兩種：`concept`（講原理）與 `screen`（要看到電腦畫面的操作）。這是內容的性質，不是風格。
- `show` 是給排畫面段看的需求，用一般的話寫（「兩個箱子，數字從左邊搬到右邊」），不寫元件名。
- 提示詞 `prompts/script.system.md`：從現在的 `scene.system.md` 把「什麼叫好的分鏡」裡跟內容有關的規則（演出過程不是念字、因果清楚、常見錯誤值得演、操作步驟給備案）與整段旁白規則搬過來，引用 `{{NARRATION_STYLE}}`。
- 驗證沿用現有的旁白檢查（`narration_problems`、`ai_tone_problems`、字數與秒數），加上：每頁有 `spine` 與 `show`、每頁 1–4 句。
- `review.md`：先列每頁 `spine` 的骨架順序，再列逐句旁白（沿用 `storyboard.py` 現在產 `review.md` 的格式）。

### 2. 風格能力表：`video_engine/styles/<風格>.json`

```json
{
  "id": "chalk", "name": "黑板",
  "types": {"icon": ["draw", "show", "blink", "erase"], "note": ["write", "show", "erase"], "vscode": "*"},
  "marks": ["circle", "underline", "callout"],
  "layouts": [
    {"id": "center",  "shape": {"stack": "ids"}, "max": 3},
    {"id": "row",     "shape": {"row": "ids"},   "max": 3},
    {"id": "two-col", "shape": {"row": [{"stack": "ids"}, {"stack": "ids"}]}, "max_per_col": 2},
    {"id": "screen",  "shape": {"stack": ["vscode"]}, "for_kind": "screen"}
  ],
  "keep": false,
  "line_extras": ["key"],
  "prompt": "styles/chalk.stage.md"
}
```

- 手帳的表列出目錄全部 15 種、自由巢狀的 `stack`／`row`、`keep: true`。
- 表的內容必須和實際畫得出來的一致。加一個測試：能力表列的每個 type／動作，都真的拿去畫一次，畫不出來就失敗（不能只比對兩份清單）。
- 黑板現在寫死在程式裡的限制（`storyboard.py` 的 `BOARD_TYPES`、`CENTER_MAX`、`COL_MAX`，`board.chalk.js` 的 `ACTS`、`MARKS`）改成以能力表為準，不留兩份。

### 3. 排畫面段：`author.py stage --style <風格>`

- 輸入：定稿的 `script.json`、風格能力表、只含該風格會畫的元件的說明（從 `prompts/components.md` 依能力表篩）。
- 輸出：`scene.json`，格式就是現在手帳的那一種（`objects`、`scenes[].layout`、`beats[].say/do`），兩種風格共用同一個驗證器 `compile.py`。
- 每個 `script` 的頁對應一個 scene，順序、句數、`say`、`spoken` 逐字相同。驗證器比對，不同就退件。
- 版面只能用能力表列的形狀；type 與動作只能用表裡有的。違反就退件重寫（沿用現有的修正迴圈）。
- `show` 要求的東西這個風格畫不出來時：LLM 用表裡有的元件盡量表達，並在輸出的 `gaps` 寫一筆（哪一頁、原本想畫什麼、改用什麼）。程式把它附加到 `gaps.jsonl`。沒寫 `gaps` 卻整頁只有文字，驗證器要提醒。
- 風格專屬的每句附加欄位由能力表的 `line_extras` 開放。黑板的 `key`（黑板上留的關鍵詞）屬於這一類，由排畫面段產生。
- 提示詞分兩份：共用的 `prompts/stage.system.md`（怎麼把 `show` 變成元件與動作、cue 規則、少即是多）＋各風格一小段（黑板：只畫原理、程式放電腦畫面、圖要大；手帳：同一主角用 `keep` 帶下去）。

### 4. 黑板吃 `scene.json`

- 新程式取代 `storyboard.py`：讀 `script.json`＋黑板的 `scene.json`，產出黑板下游現在吃的那些檔案（`script.md`、`pages.json`、`screens.json`、`objects.json`、`keys.json`、`leads.json`、`holds.json`、`recap.json`）。下游（`pages.py`、`f5_story.py`、`sync_film.py`、starter）不動。
- 模板由版面形狀判斷（能力表的 `layouts`），不另外寫模板名。
- 黑板的章（左上角的章名）：連續幾頁 `title` 相同就算同一章，不另外加欄位。
- `lead`（先畫後講的秒數）不由 LLM 寫：一句的第一個動作是沒有 cue 的 `draw` 時自動給預設值。
- 刪除：手寫 `storyboard.json` 格式、`storyboard_to_scene.py` 與它們的測試。舊片的資料夾留著當紀錄，不再保證能從 `storyboard.json` 重建。

### 5. 配音一次

- 文本定稿後逐句用 F5 合成，以「唸的文字＋參考音＋seed＋讀音表」為快取鍵（`tts_f5` 現有機制）。
- 兩種風格各自組裝自己的時間軸（黑板有板擦與先畫後講的停頓，手帳沒有），但都從同一批逐句音檔組，不重新合成。
- 手帳改用實測時間（`compile.py --timing`），不再用估的。

## 驗收

1. 沒有 LLM 的部分全部有測試：`script.json` 與能力表的驗證、排畫面結果的比對（`say` 不變、版面與型別在表內）、黑板從 `scene.json` 產出下游檔案。
2. 用一份手寫的假 `script.json`＋兩份手寫的 `scene.json`（黑板、手帳各一），不花錢跑完兩種風格的建置與版面檢查。
3. 能力表與實際畫法一致的測試通過。
4. 全套測試通過；宣稱沒動到的舊教材 44 張 PNG 逐位元組基準不變。
5. 真教材實跑（付費 LLM＋Colab 配音與渲染，**每一步先問使用者**）：同一份文本出黑板、手帳各一支審片版，連同 `review.md` 與 `gaps.jsonl` 交給使用者看。

## Claude 代為決定的事（審文件時請特別看）

- 這次不碰 `plan`（拆單元、問題鏈），只處理它之後的兩段。
- 風格由人用參數指定，AI 自動選留到之後。
- `kind` 只分 `concept`／`screen` 兩種。
- 黑板的關鍵詞 `key` 算畫面的一部分，由排畫面段產生，不放在文本裡。
- `lead` 由程式給預設，不讓 LLM 寫秒數。
- 刪掉手寫分鏡格式後，舊片不保證能重建（成片與資料夾都留著）。刪除排在最後一步。printf 片原本排的 b25（重挑 13 句）使用者 2026-11-10 決定不出了，所以不用等它。
- 黑板的章用「連續同標題的頁」推出來，不加欄位。
- 文本先寫、畫面後排，代表旁白可能講到某個風格畫不出來的東西；這時記成缺口、用現有元件盡量表達，不回頭改旁白。
