# 黑板＋電腦畫面混合影片（B 版：簡化版 VS Code）

使用者 2026-10-23 看完黑板 v3／手帳 v2 後的方向：真實截圖不適合貼進版面；講原理用黑板，示範操作時整個畫面變成電腦螢幕。先做 B 版（畫出來的簡化 VS Code），效果好就不補截圖、不做 A 版。

## 範圍

只動 `video_engine/out/vscode_printf_chalk` 這支片與它的 story（`docs/experiments/2026-10-22-vscode-printf/video/chalk-story/`），以及 `video_engine/explainer/f5_story.py`。不動岚叔 vendor 原始碼、不動 board／手帳引擎。旁白沿用現有 F5 快取，只有文字變了的句子會重唸（本機 GPU）。

## 流程

| 段落 | 句子 | 內容 |
| --- | --- | --- |
| 黑板 | 1–7 | 問題 → 原因（緩衝區、輸出面板不能打字）→ 網路上說加 fflush |
| 轉場進電腦 | 7 → 8 之間 | 鏡頭移到一塊專用的「螢幕」面板，粉筆畫出螢幕外框，框內淡入簡化版 VS Code，鏡頭推近到螢幕充滿整個畫面 |
| 電腦 | 8–12 | fflush 後唯讀 → 齒輪 → 設定 → 搜尋 → 打勾 → 再執行，終端機輸入 5 成功 |
| 轉場回黑板 | 12 → 13 之間 | 反向：鏡頭退回螢幕面板，再走到下一章 |
| 黑板 | 13–15 | Ctrl＋Alt＋M、不停會編譯失敗、結語與複習 |

## 設計

**story 擴充。** story 資料夾新增 `screens.json`：`[{"lines": [8, 9, 10, 11, 12], "kind": "vscode"}]`，由 `f5_story.py` 寫進 `story.screens`。螢幕段的句子不進 `pages`；`pages.json` 驗證時把它們排除。

**黑板版面。** 螢幕段在版面上佔一塊面板（一般大小 1840×1020），排在它前後兩章之間，跟著環形走位。面板中央是 16:9 的螢幕區（1600×900），鏡頭推到螢幕區寬度等於 1920 時就是全螢幕。

**螢幕層。** 簡化版 VS Code 畫在不套粉筆雜訊遮罩的獨立 SVG 層（同現有截圖用的 photo layer），座標用螢幕面板座標。元素：上方標題列、左側活動列（含左下齒輪）、檔案總管、編輯區（s2_scanf_fflush.c 程式碼）、下方面板（輸出／終端機分頁）、齒輪選單、設定視窗（搜尋框、Run In Terminal 勾選框）、滑鼠游標。字級放大、細節拿掉，配色取自 VS Code 深色主題的近似色，寫成 beats.js 內一組常數（螢幕是「被畫的物件」，不屬於黑板 theme）。

**螢幕裡的動作。** 游標移動與點擊、選單展開、逐字打字、勾選、終端機逐行出現；標註用螢光筆風格（黃色半透明底線、紅色手繪圈、箭頭），跟粉筆區分。每個動作綁在旁白的詞上（`api.at`），標註位置由元素框計算，不寫螢幕座標。鏡頭在螢幕內可再推近到正在操作的區域，操作完退回全螢幕。

**節奏：邊講邊長。** 所有頁（黑板與螢幕）的圖分散在整句旁白裡、講到哪畫到哪，句末剛好畫完。不加刻意停頓；但換頁時鏡頭移動需要的時間（約 0.9 秒）旁白不講話：`f5_story.py` 在換頁處把句間空檔補到至少 0.9 秒（同頁內的句間空檔不變）。

**走位修正。** 環形下排的章節內，頁也改成由右往左排，鏡頭走成「上排往右 → 往下 → 下排往左」的蛇行，不再每章跳回左邊。

**邊框卡頓。** 黑板 v3 轉場時邊框卡頓的原因未查。實作時先用逐格擷取定位原因、回報，再決定修法，不先改。

**音效。** 不加移鏡咻聲、換章敲板聲（已拿掉）。螢幕段：點擊一聲輕「喀」、打字輕敲，音量低於旁白。

## 驗收

1. `hyperframes check` 0 error；`grep -c "placeholder(" beats.js` = 0；沒有 `Math.random`／`Date.now`。
2. 旁白 `story.lines` 句句不重疊；換頁處空檔 ≥ 0.9 秒。
3. 每頁每個元素都在所屬頁（或螢幕區）內；標註落在目標元素框內；元素兩兩不重疊（標註壓在目標上除外）。以 headless 瀏覽器逐句句末取樣量測。
4. 鏡頭走位：相鄰兩頁的位移方向依序為右…右、下、左…左，不出現回頭跳躍（結尾回到左上報頭、拉遠看全板除外）。
5. 好不好看交使用者看片判斷，不自行評價。
