# 投影片版型多樣化 — 設計文件

**日期**：2026-08-26
**範圍**：只動幾何。配色、內容結構（schema／prompt）、動畫層一律不碰。

---

## 1. 問題

五份教材、22 頁投影片，畫面幾何**完全一樣**：頂部一張標題卡、下方一張內容卡、所有文字置中於 `x=960`、示意圖永遠掛在條列正下方。連續看四五頁像同一張投影片在換字。

實測的內容分布（這是設計的依據）：

| 內容 | 頁數 | 幾乎固定對應的 role |
| --- | --- | --- |
| `figure/compare` | 6 | hook |
| `code` | 5 | walkthrough |
| `figure/boxes` | 4 | concept |
| `figure/steps` | 4 | pitfall |
| 純文字 | 3 | 僅舊的 v3 教材 |

**關鍵觀察**：一堂課的序列固定是 `compare → boxes → code → steps`。內容型態每頁都不同，只有幾何沒跟著變。因此**讓幾何跟著 figure kind 走，同一堂課內就自然不重複**——不需要靠頁次輪替當主要機制（輪替只用來處理同一種 kind 在一堂課裡重複出現的情況）。

## 2. 為什麼渲染層改得動，而且只需要改渲染層

三層契約已經付過這筆帳。動作只寫語意代號（`p3_code:L4-L6`），座標全部從 `render_slides.py` 實測產出的 `layout.json` 查。已查證的下游相依：

- `compile_timeline.py:32,42,95,103` — 查 boxes 取座標
- `render_video.py:149,163,207,234,278` — 聚光燈、雷射、浮現裁圖、鏡頭推近全部吃 box
- `validate.py` — 對幾何**零假設**
- `compile_timeline.py:133-139` `reveal_ms()` — 依 box 佔畫面比例分級進場時長，會自動跟著新版位調整

所以改繪製座標，動畫免費跟上。**不需要**動 schema、prompt、時間軸編譯器或影格渲染器。

## 3. 兩條最高原則

使用者指定的優先序：**順暢**、**不耦合**。它們直接推導出兩個硬決定。

### 3.1 順暢 → 錨點不動

換頁是 420ms 的交叉淡化（`motion.TRANS_MS`）。若相鄰兩頁的卡片外框不同，淡化過程中框線會互相穿插，看起來是髒的，而不是變化。

**硬規則：所有版型的 `HEADER_BOX` 與 `CONTENT_BOX` 外框逐像素相同。變的只有內容卡的內部分割。**

這條直接否決了 AGY 建議的「hero 版型把 header 壓縮成 120px 高」——那會讓標題在換頁時上下跳。

### 3.2 不耦合 → 幾何算式與繪製分離

新增 `video_engine/layout.py`：**純函式，不 import PIL、不碰檔案**。輸入一頁的語意內容，輸出一組具名矩形區域。`render_slides.py` 只負責把東西畫進被指定的區域。

好處是幾何可以**不畫圖就測**——版型選擇、容量計算、降級邏輯全部是純函式的單元測試，不需要比對圖片。

## 4. 版型

四種。刻意壓到四種：版型數量是負債不是功能，每一種都必須有真實資料在跑。

| 版型 | 觸發條件 | 幾何 |
| --- | --- | --- |
| `stack` | 保底：純文字頁、以及任何容量不足而降級的頁 | 現況。條列與圖垂直堆疊、整塊置中於內容卡 |
| `split` | `figure.kind in ("boxes", "steps")` | 內容卡切成左右兩欄。文字欄**靠左對齊**（破除全置中），圖欄放 figure。左右由頁次奇偶鏡像 |
| `stage` | `figure.kind == "compare"` | 條列收成內容卡頂部一列，compare 拿下方整片寬度，面板加寬、字級提升 |
| `code` | 該頁有 `code` 元素 | 依行數決定行距與字級，整塊**垂直置中**於程式碼卡 |

### 4.1 窄欄裡的 figure 改直向繪製

`split` 把 figure 塞進約 780px 寬的欄位。現行 `boxes`／`steps` 是橫向一排（`FIG_MAX_W = 1560`），硬塞進半欄會把每格壓到 180px、字級掉到下限。

因此 figure 繪製器要能依**拿到的區域寬度**自行決定橫向或直向：寬度不足以橫排時改成直向堆疊，`steps` 的箭頭跟著轉成向下。

這是 figure 繪製器自己的性質（「窄就直排」），**不是第五種版型**——版型只管切區域，不管 figure 內部怎麼畫。這是 3.2 那條分離原則的直接應用。

### 4.2 鏡像只處理重複

`split` 的左右由頁次奇偶決定。它存在的唯一理由是：同一堂課出現兩頁同 kind 的 figure 時（實測 `c_loop` 的 p1 與 p4 都是 compare），純內容驅動會讓它們長得一樣。**不是為了製造變化而輪替**——主要變化來自 kind 對應不同版型。

## 5. 不變量

任何實作都不得違反。這節就是驗收清單。

1. **`base` 與 `full` 兩張圖的幾何逐像素相同。** `hidden` 元素只畫在 `full`，但**版位計算必須含 hidden**。`render_video` 的逐條浮現是從 `full` 裁該區域疊回 `base`——版位一旦因 hidden 而不同，裁出來就是錯位的畫面。現行程式碼靠 `n_bullets` 不分 hidden 計數守住這條。
2. **所有可定址代號都要有量測框**，一個都不能少：元素 id 本身、`{id}:L{n}`（程式碼行）、`{id}:i{n}`（boxes／steps 項目）、`{id}:l{n}`／`{id}:r{n}`（compare 左右項）、`{id}:caption`。缺一個，指到它的動作就會靜默失效。
3. **任何輸入都不得溢出所屬區域。** 條列超量、程式碼過長、compare 項目過多，一律先縮字級／行距，仍不足則降級為 `stack`。降級是設計的一部分，不是失敗。
4. **決定性。** 同一份 `lesson.json` 重跑兩次，輸出逐位元組相同。不得引入隨機或時間相依。
5. **配色不動。** `themes/warm.json` 一個位元組都不改，繪製器不得寫死任何顏色。
6. **`lesson.json` 不出現任何像素座標。** 版型由內容組成推導，不由教材指定。
7. **`HEADER_BOX` 與 `CONTENT_BOX` 外框在所有版型中相同**（見 3.1）。
8. **不新增第三方依賴。** 只用 Pillow 與標準函式庫。

## 6. 明確不做

- **不動 `prompts/lesson_content.system.md` 與 `lesson.schema.json`。** 放寬內容結構（允許 code 與 bullet 同頁之類）是下一輪的事。先有承接的容器，再放寬內容；反過來會產出渲染器接不住的組合。
- **不做動態約束求解／自研 Flexbox。** 相鄰兩頁因為差兩個字而讓卡片寬度跳動，在靜態簡報看不出來，在 420ms 交叉淡化裡會變成閃爍。
- **不把 `slide.note` 畫到畫面上。** schema 對它的定義是「給 LLM 的補充說明，**不會顯示在畫面上**」。AGY 的方案曾建議把它當右欄金句卡，那會把寫給模型的提示話術端到觀眾面前。
- **不改配色、不加新色。** 多樣性只來自空間與對齊。
- **不做隨機版型。** 見不變量 4。

## 7. 驗證策略

全部免費——`render_slides.py` 不碰 LLM 也不碰 TTS。

| 層次 | 方法 |
| --- | --- |
| 幾何算式 | `layout.py` 是純函式，直接單元測試：版型選擇、容量、降級、鏡像 |
| 量測框完整性 | 對五份教材跑繪製，斷言每個可定址代號都出現在 `layout.json`，且都落在所屬區域內 |
| 不變量 1 | 同一頁分別以「全部 hidden」與「全部不 hidden」計算版位，斷言兩者的框完全相同 |
| 不變量 4 | 同一份教材連跑兩次，PNG 逐位元組比對 |
| 重構安全網 | 引入 `layout.py` 但仍只有 `stack` 的那一步，五份教材 44 張 PNG 必須與改動前**逐位元組相同**（基準已建立：正規化路徑後 md5 `bf7997d90b8fd8b6863eb43178f9c28f`） |
| 視覺 | 產出改動前後對照圖交使用者確認。不自行截圖判定好壞 |

## 8. 已知的既有缺陷（本輪順帶修掉）

`prompts/lesson_content.system.md` 規則 7 允許程式碼 8–16 行，但固定 42px 行距下 15 行剛好貼齊 `CODE_BOX` 底線、**16 行溢出 42px**。既有語料最長 15 行，差一行就爆版。已由 `code_metrics()` 依行數自適應行距與字級修掉，15 行以內輸出逐像素不變。
