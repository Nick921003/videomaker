# 版面模式選擇器 — 設計文件

**日期**：2026-08-27
**範圍**：讓使用者在前端挑投影片的版面模式。只動版型「選擇」那一層，幾何算式、配色、schema、prompt、動畫層一律不碰。

---

## 1. 現況

版型完全由內容組成推導，**刻意不隨機**（不變量 4：同一份教材重跑兩次逐位元組相同）：

| 這頁有什麼 | 版型 |
| --- | --- |
| 程式碼 | `code` |
| 單張 `compare` 圖 | `stage`（條列收成上方一帶，圖吃滿寬） |
| 單張 `boxes`／`steps` 圖 | `split`（左右分欄，左右由頁次奇偶鏡像） |
| 純文字、多張圖、有 `image` | `stack`（垂直堆疊、整塊置中） |

前端只有兩個輸入：檔案、預期秒數。**沒有任何版面選項。**

## 2. 要做什麼

前端加一組三選一，決定版型的**選擇模式**：

| 模式 | 值 | 行為 |
| --- | --- | --- |
| 自動（預設） | `auto` | 現況，依內容推導 |
| **雙欄** | `split` | 只要有單張圖就左右分欄——**`compare` 也走分欄**，不再吃滿寬 |
| 置中單欄 | `center` | 一律 `stack`，回到版型改造之前的樣子 |

程式碼頁在任何模式下都是 `code`（那不是「版面」而是內容型態，硬要塞進分欄只會把程式碼壓成不可讀）。

模式只改變**選擇**，不改變任何一種版型的幾何。四個容量守門照舊：放不下就降級，最後一級才 `raise`。所以 `split` 模式遇到塞不進半欄的圖，仍會自動退回 `stack`——使用者選的是偏好，不是強制。

## 3. 決定性不變

模式是**顯式輸入**，不是隨機。同一份教材 + 同一個模式 → 逐位元組相同的輸出。不變量 4 完全保留。

## 4. 資料怎麼流（實查過的整合鏈）

```
web/index.html  FormData 欄位 layout
      ↓
serve.py  parse_multipart()  ← 目前只解析 file 與 sec
      ↓
serve.py  real_runner(material, sec)  → 加第三個參數 layout
      ↓
run.py    --layout（照 --sec 的 opt() 慣例解析）
      ↓
render_slides.py  --layout（附加在 argv 尾端，argv[2] 仍是 out_dir）
      ↓
layout.pick_variant(slide, mode)  /  layout.regions_for(slide, index, mode)
```

**只有 `slides` 階段吃這個參數。** `actions`／`validate` 用 `--sec`，兩者互不相干。

## 5. 硬性約束

沿用 `CLAUDE.md` 的全部不變量，另加：

1. **`layout.py` 仍須零 import、無副作用。** 模式只是多一個帶預設值的參數。
2. **既有呼叫端不得被迫修改。** `pick_variant(slide)`、`regions_for(slide, index)` 兩參數呼叫必須維持現有行為（`mode="auto"` 是預設值）。現有 127 則測試一則都不准改。
3. **`auto` 模式的輸出必須與現在逐位元組相同。** 五份教材 44 張 PNG 重跑的正規化 md5 不變，這是這輪的回歸閘。
4. **未知的模式值要明確失敗**，不得靜默當成 `auto`——那是「以訊號缺席推論成功」的形狀，這個專案已經被咬過四次。
5. **前端只准動 `web/index.html`。** 暖色票（`#F4EDE2` / `#FBF7F0` / `#DFD2BF` / `#3B322A` / `#4B4238` / `#B85C38` / `#A0673F` / `#EFE6D8` / `#DCCDB6` / `#F2D9A0`）一個都不准換，不准引入 CDN、不准加框架。

## 6. 已知風險

`compare` 在 `split` 模式下會被塞進約 810px 的欄位，兩個面板各約 375px。`fig_height()` 對 `compare` **不看寬度**（回傳 `64 + n*74 + caption`），所以高度守門擋不住「橫向擠爆」——面板內的字會由 `fit_font` 一路縮到下限 16px。

這不是阻擋條件（使用者選了就是要看分欄），但要在報告中實測回報：每邊 2／3／4 項時，`compare` 在 810px 欄位裡的實際字級與是否溢出面板。

## 7. 驗證

全部免費（`render_slides.py` 不碰 LLM 也不碰 TTS）。

| 項目 | 方法 |
| --- | --- |
| `auto` 零回歸 | 五份教材 44 張 PNG 正規化 md5 不變 |
| 三種模式都畫得出來 | 五份教材 × 三種模式 = 15 次渲染，零例外 |
| 模式真的有差 | 同一份教材三種模式的版型分布必須不同 |
| 決定性 | 同教材同模式跑兩次逐位元組相同 |
| 不變量不破 | 每個模式都要：零越界、零代號缺漏、卡片外框簽章仍為 1 種 |
| 壞模式值 | 明確失敗，不是靜默退回 `auto` |
| 視覺 | 產出三種模式的對照圖交使用者確認，**不自行判定好壞** |
