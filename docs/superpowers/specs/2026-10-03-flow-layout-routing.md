# 流程圖排版與連線修復

使用者指出現有C語法影片13秒：return 0應接在printf後面，現在被四欄上限折到下一排，連線和箭頭不清楚。沿用現有分鏡、音訊、字幕與24fps，只修實際paper renderer。

flow依實測文字挑可讀欄數，不固定最多四欄。選擇最多可讓所有既有／更新後短標籤在每格至多兩行的欄數，字級38不為硬塞整排而縮小。現有五節點應同一列由左至右。

連線幾何從當前變換後slots量測取得。相鄰同列用左右邊中點；跨列用前節點底邊／後節點頂邊中點，走兩排間空隙的直角折線。箭頭尖端方向依最後一段路徑決定。metadata與實際繪圖使用同一份path/head，避免兩套公式漂移。

驗收：第13秒五節點同列，return0位於printf右側；四個連線完整。長標籤、跨排、提示顯示／退出與鏡頭變換的連線須接在對應slot邊界，不能穿過其他節點或正文。先以8–16秒同聲音短片和實際編碼影格驗收，再輸出整片。原board/timeline/WAV/SRT的SHA256維持。

使用者提供示範prompt作為流程參照，不直接切換Canvas、30fps或F5-TTS，也不新增另一個主題的付費影片。這次補足具體排版／路徑檢查與短片閘；更大的製作流程改造另行規劃。


驗收補充：flow排字保留ASCII識別字及短中文片語，避免stdio.h與已載入之間把「入」孤立；候選欄數亦檢查完整Latin詞寬。明確三行標籤在沒有兩行版型時保留單欄和原換行，使用既有可讀字級閘。
