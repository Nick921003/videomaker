# 圖示元件＋黑板吃分鏡（最小版）

日期：2026-10-31　狀態：設計待使用者同意

## 為什麼做

目標是 AI 只寫分鏡、挑元件、填字，不寫元件程式；**換風格只換皮，分鏡一個字都不改**（使用者 10-25、10-29、10-31 三次確認）。現況離這個目標差兩件事：

1. 小圖示（沙漏、鎖、鍵盤……）每支片手畫。手帳的 `icon` 只有齒輪；printf 黑板片的沙漏、鎖、鍵盤、Ctrl／C 鍵帽寫死在 `beats.js`。
2. 黑板只有「電腦畫面」頁吃分鏡（`screen`＋`do`，經手帳編譯器驗證、`vscode.chalk.js` 照逐字時間畫），其他頁還是每支片手寫 `beats.js`。

**取捨**（使用者 10-31 確認）：多樣性的上限就是元件目錄。不夠時一起設計新元件或上網找參考加進目錄，不回頭替單支片手寫畫面；元件做不到的畫面退成文字並記進 `gaps.jsonl`，當作下一個補什麼的依據。

本案把圖示做成元件，並把路線圖階段3「黑板吃元件目錄」的最小版併進來，用**一份分鏡出手帳、黑板兩版展示片**來驗證統一工作流（使用者 10-31 選定）。

## 目標

- 一套圖示元件，形狀只寫一份，鉛筆（手帳）、粉筆（黑板）、仿真（文章 PNG）三種皮膚共用。
- 分鏡用**意思**叫圖示；一個圖示對多個意思（使用者 10-31：鎖＝固定／不變／沒變化／不能改；沙漏＝等待／僵住／無限）。
- 圖示有三個專屬動作：畫出（照筆順）、閃爍、擦掉。
- VS Code 的 `tip` 提示框抽成通用註記，任何元件的錨點旁都能掛。
- 黑板的置中／雙欄頁也吃分鏡的 `objects`＋每句 `do`，不寫專屬程式。
- 一支用到全部圖示的展示片，同一份分鏡出手帳版與黑板版。

## 不做（留給後面階段）

- 清單、管線、堆疊、變數等其他元件的粉筆皮膚（階段2）。展示片黑板版只用本案有粉筆皮膚的元件：`icon`、`note`、`vscode`。
- printf 片改成零專屬程式重出、`chalk_film.py` 一支指令（階段3 後半）。printf 的 `beats.js` 本案**不動**，b25 照舊。
- 電路領域包（溫度計、閃電、感測器、斷路器），排第二批。
- 白板風格、兩套繪圖引擎（Canvas／HyperFrames）要不要收成一套（階段5 再決定）。
- 依教材自動挑風格。

## 反目標（做出來也算失敗）

- 換風格要改分鏡，或黑板版要補任何一行專屬 JS。
- 意思對不到圖示時默默換成別的圖、或什麼都不畫（「檢查壞掉卻顯示通過」，見記憶 fail-open-checks）。
- 圖示畫出框外、和別的元件疊在一起，量測閘卻是綠的。
- 同一份分鏡跑兩次畫面不同（決定性）。

## 怎麼做（做法比較）

**展示片的驗收方式**（使用者選 2）：① 型錄片（全部圖示排格子）＋ printf 片；② 一支用到全部圖示的教學片；③ 只出 PNG 總表。選 ② 的理由：要看圖示放進真內容裡的效果，不是只看格子。

**黑板怎麼吃分鏡**（使用者選「併進來」）：① 本案只做圖示，黑板展示片手寫 `beats.js`——做完階段3 又要重寫，違反統一工作流；② 先做完整階段3 再回來——圖示要等很久才看得到；③ **本案做階段3 的最小版**（只吃 `icon`／`note`／`vscode`＋置中／雙欄）——選這個。

## 設計

### 1. 圖示形狀：`video_engine/components/icon/`

比照 `components/vscode/` 的切法，純函式、零 DOM、不碰檔案：

- `shapes.js`：`strokes(name, opts) → [{pts, w, part}]`。座標在 100×100 的格子內，**陣列順序就是筆順**（先外框後細節，參考 Fu et al. 2011；見參考紀錄）。弧線預先取樣成點。`w` 是相對粗細等級（`main`／`detail`），不是像素。`keycap` 另回 `{text}`。
- 只用線條、不填色（參考 Lucide 規範：固定網格、圓頭圓角、留邊）。筆觸、抖動、顏色全交皮膚。
- `svg.js`：strokes → SVG 字串（仿真皮膚，文章 PNG 用；`export_png.py` 照 VS Code 那支的做法）。

### 2. 契約：`board/catalog.json` 的 `icon`

- `req: ["name"]`、`opt: ["caption", "tone", "text", "size"]`。`name` 可以寫圖示名稱或任何一個意思。
- 新增 `means`：`{圖示名稱: [意思…]}`。編譯器把意思解析成圖示名稱；同一個意思不得出現在兩個圖示下（編譯目錄時就擋）。
- **對不到就報錯**，訊息列出最接近的三個意思（字元重疊排序），不退化成文字。
- 動作：
  - `draw`：照筆順畫出；時長依筆畫數（每筆約 0.12 秒，夾在 0.5–1.6 秒），`blocks: true`。圖示被 `show` 時也走這個畫法。
  - `blink`：閃到 `until`（另一句的 cue 或句號）為止；沒寫就閃到這頁結束。
  - `erase`：擦掉，0.4 秒。
- 錨點：`icon` 本身就是可定址的框；`{id}:caption` 給說明文字。

### 3. 通用註記 `tip`

- 新增通用動作：`{act: "tip", target: "<任何錨點>", text, tone}`，外觀照 `vscode` 的 tip（圓角框＋小三角指向錨點）；下一個指向同一元件的動作出現就收，或寫 `until`。
- 位置規則：優先錨點右側，放不下換左、上、下。位置在繪製時決定（`compile.py` 沒有幾何資訊）；四邊都放不下就**量測閘失敗**（手帳 `check.py`、黑板的錨點閘），不准畫到區域外（硬性不變量 3）。
- **`vscode` 自己的 `tip` 不動**（沒有 target、貼在 `panel:end` 右側並夾在面板內，`model.js` 的 `tipBox`）：printf 分鏡有用到，改位置會讓 b25 畫面跑掉。兩者只共用外觀常數。

### 4. 三種皮膚

| 皮膚 | 檔案 | 怎麼畫 |
|---|---|---|
| 鉛筆（手帳） | `board/runtime/components/icon.js`（改寫） | strokes 縮放到元件框 → `api.ink(pts, p, {seed})`，`p` 照筆順分配 |
| 粉筆（黑板） | `explainer/chalk/kit/icon.chalk.js`（新） | strokes → path 交給 kit 的粉筆筆畫；閃爍用 printf 已驗證的 `K.fade` 分段法（不寫 `style.opacity`） |
| 仿真（PNG） | `components/icon/svg.js`＋`export_png.py` | 等粗線、主題色 |
| 粉筆 `note`（黑板） | `explainer/chalk/kit/note.chalk.js`（新） | 五種 style 對 kit 字級：headline 60、body 46、accent 46（`accent` 語氣）、code 46（Patrick Hand）、small 38；超過欄寬自動換行，換行後仍放不下就縮字級，最小 30（KIT.md 的下限）；寫字走 kit 的逐字書寫 |

顏色只走 `tones.json` 的語氣（硬性不變量 6），`tone` 沒寫用 `ink`。

### 5. 黑板吃分鏡（最小版）

- 分鏡格式沿用 `storyboard.json`：置中／雙欄頁也可以寫 `objects`（與 `scene.json` 同格式）和每句 `do`，`storyboard.py` 交手帳 `Compiler` 驗證（同電腦畫面頁的 `screen_actions`），寫進新的 `objects.json`。
- 版面文法（照記憶「版面模板要穩」，不開放巢狀）：置中頁＝最多 3 個物件由上而下置中；雙欄頁＝每個物件寫 `col: "left"|"right"`，每欄最多 2 個由上而下。超過就是編譯錯誤。
- 物件在被 `show`／`draw`／`write` 之前不出現；照「先畫後講」，畫出類動作排在該句開口前的 lead 時段。
- 頁上原有的 `main`／`support`／`draw`／`point` 照舊只是給人看的說明文字，繪製不讀。
- 新增通用黑板轉接 `explainer/chalk/kit/board.chalk.js`：讀 `objects.json`，依模板把物件排進 `api.tpl` 的格子（置中：直排置中；雙欄：照 `layout` 分左右），照逐字時間放動作（排程沿用 `vscode.chalk.js` 的 `schedule`：有 cue 從那幾個字開口起跑，沒有的從這句開始畫的時刻起跑）。
- 黑板專案從新的 `explainer/chalk/starter/` 開：`index.html` 取 printf 片的版本（板擦換頁、平移、電腦畫面段），加上 `board.chalk.js`／`icon.chalk.js`／`note.chalk.js` 的掛載點，`sync_film.py` 把 `objects.json` 帶進 `lib/`。`index.html` 是**風格層**，每種風格改一次；每支片的專屬程式指的是 `beats.js`。
- starter 的 `beats.js` 是空樣板（不畫任何佔位）。「黑板版沒有專屬 JS」的驗法：展示片的 `beats.js` 與樣板逐位元組相同。不做「同頁有 objects 又有手寫內容」的偵測（`beats.js` 是自由 JS，靜態看不出來，做了也是會失效的檢查）。
- **先畫後講**照舊：新畫的東西落在開口前的 lead 時段，開口後只做點名（圈、底線、閃、擦）。

### 6. 一份分鏡兩種出片

- 分鏡的主格式是 `storyboard.json`（有每頁一句話骨架、模板、lead，使用者審的就是它）。
- 新增 `storyboard_to_scene.py`：storyboard → 手帳 `scene.json`。對應：頁→scene；置中→`stack`；雙欄→`row` 裡左右各一個 `stack`；電腦畫面頁→含 `vscode`＋`cursor` 的 scene（手帳已有鉛筆版 VS Code）；`end` 那句→最後一個 scene 的最後一句；`recap`→最後一個 scene，用手帳的 `list` 元件列出各章重點。每句 `say`／`do` 照搬。手帳管線照舊（compile → build → check → export）。
- 時間：F5 配音後的 `story.json` 給黑板（逐字）。手帳的 `timing.json` 由同一份 `story.json` 換算，每句的 t0 取「開始畫的時刻」（含 lead），所以手帳也是先畫後講。

### 7. 展示片

- 題材：一支作業程式從寫到交出去。主線依序用到 A 組 24 個；結尾一段「聊聊」用 B 組 7 個。
- 一頁一到兩個圖示、只用置中／雙欄（記憶 layout-templates-steady、teacher-pacing-feedback）。片長約 4–5 分鐘。
- **先交「每頁一句話」骨架給使用者審順序**（記憶 narrative-spine-first），通過才寫逐句旁白。旁白照 `narration_style_tw.md`，講意思不念符號。
- 配音（F5）與渲染只在 Colab 跑（記憶 render-off-local），開跑前另外徵得同意。

## 驗收

1. `catalog.json` 的 31 個圖示都有形狀、`means` 無重複；`fixtures/icon_full.scene.json`（全部圖示＋三個動作＋`tip` 四邊放置）過手帳量測閘（越界、重疊、縮放下限、決定性）。
2. 負向：分鏡寫一個不存在的意思，`compile.py` 必須失敗並列出建議；把某個意思同時放進兩個圖示，載入目錄必須失敗。
3. `vscode` 自己的 `tip` 不受影響：新增一份含 `tip` 的 VS Code fixture，改動前後匯出逐位元組相同；printf 黑板片 `lib/` 重新同步後與改動前相同。
4. 三種皮膚各出一張 31 格總表 PNG，交使用者看。
5. 展示片分鏡一份，`storyboard_to_scene.py` 轉出的手帳版、黑板版都建置成功：手帳 `check.py` 過；黑板 `screen_check.js`（擴充到 `objects` 頁）＋`npx --yes hyperframes@0.8.81 check` 0 錯；黑板版**沒有任何專屬 JS**（`beats.js` 只剩樣板）。
6. 兩版在 Colab 渲染，並排交使用者審。
7. 全套測試綠；同步清單 `tools/video_skills_sync.py` 的 `INCLUDE` 補上新檔。

## Claude 代為決定的事（審文件時請特別看）

實作者角度檢查（子代理）提出 6 個缺口，都屬技術細節，Claude 依記憶與現有程式決定如下：

1. 黑板 `note` 要新做粉筆皮膚（原文件漏了），字級對 KIT.md。
2. 黑板 starter 用 printf 片的 `index.html` 改成；`index.html` 算風格層，`beats.js` 才是每支片的專屬程式。
3. 通用 `tip` 另做，`vscode` 自己的 tip 不動，以免 b25 畫面跑掉；放不下由量測閘擋，不在編譯期擋。
4. 版面不開放巢狀：置中最多 3 個物件、雙欄每欄最多 2 個。
5. 手帳版：電腦畫面頁用鉛筆 VS Code、`recap` 用 `list` 元件、時間含 lead 所以也先畫後講。
6. 不做「同頁混寫」偵測，改成驗 `beats.js` 與空樣板逐位元組相同。
7. （寫計畫時對抗審查後補）通用註記改名 `callout`：與 `vscode.tip` 同名會讓錨點被安靜吃掉。其餘技術調整見計畫檔最後一節。
- 2026-11-10 後續修正：黑板置中／雙欄頁原本只接圖示、文字、標註框，補上 `circle`／`underline`（照物件的框畫，目標擦掉時跟著淡出）。
