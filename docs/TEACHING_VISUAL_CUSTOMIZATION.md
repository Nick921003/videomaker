# 教材影片的風格客製化原則

2026-10-11 使用者方向：暖色紙面／手帳為預設；三種方向皆可用，呈現應配合教材；同時要求各影片有多元性，不能每一部都長一樣。使用者先前選定的文字與手帳保留，手繪等能力仍應在適合內容時使用。

## 兩個不同範圍

每支影片內維持主視覺、語意配色、字幕與過場的連貫；不同影片可以選不同主風格與構圖。暖色手帳是使用者沒指定時的起點，不是所有題材強制套用的紙面網格或兩欄版型。固定品牌辨識不代表固定每一頁的布局。

| 主風格或呈現能力 | 優先試用的教材需求 | 可看的教學動作 |
| --- | --- | --- |
| 暖色手帳／紙面 | 觀念整理、重點關係、課後回顧 | 重點逐步整理、圈選、分類聚合 |
| 手繪／白板／粉筆 | 邊講邊推理、變數或陣列追蹤、錯誤修正 | 逐筆建構、填入陣列、擦除錯誤後重寫 |
| 工程圖 | 迴圈、控制流、資料結構、系統依賴 | 路徑描繪、唯一執行標記、尺寸與關係引線 |
| 乾淨圖表 | 操作次數、空間、量化比較 | 座標先建立、數值再出現、最後標註結論 |

選用依據是這段教材要學生理解什麼，不是每個重點隨機輪流換效果。手繪可以作整支影片的主要語言，也可以作主視覺相容的局部推理段；工程或量化也可作整支影片的主要風格。局部融合時沿用字型、語意色與字幕；整片改主风格时可有不同材質與布局，片內仍保持一致。素材資訊含是否需要深底、紙面或筆畫材質，以免把無法直接換皮的元件硬湊。

未來對話製片應先確認／建議「這支影片的主風格」，再按教學目的選動畫；可讓使用者指定、採系統建議，或要求與最近幾支影片換不同主風格。多元性應來自主題、構圖與動畫能力的選用，不能以破壞內容正確性或逐段換整套皮膚來湊變化。

這份文件記錄已確認的需求與選用原則，尚未宣稱正式 AI 路由、catalog 或全片風格選單已完成。`coherent/` 只實作暖色基底的同題材對照示範。

## 先沿用影片，再依理解回饋補強

使用者追加確認：有對應教材的既有影片就先顯示，不因進入對話而重新生成。觀看後以「這段有理解嗎？哪個地方想再說明？」接續，學生可指出不懂的重點、要求換風格或加強解釋。

| 學生回饋 | 下一步 |
| --- | --- |
| 已理解 | 繼續下一個重點 |
| 想再看某一步 | 重播或定位既有影片中的對應段落 |
| 換一種解釋／風格 | 優先找同一重點的既有另一版本；沒有合適版本才製作補強片段 |
| 某個部分還不清楚 | 保留其他已理解的部分，針對這個重點增加例子、逐步走讀或放慢節奏；找不到合適片段才生成 |
| 初次提問且沒有對應影片 | 沿用教材分析與製片流程，製作缺少的重點影片 |

例如看完迴圈影片後說「我不懂 i++ 後為什麼要回到條件」，下一段集中解釋更新、返回、再判斷的關係；可以用手繪逐筆畫出路徑，不必重新製作整堂課。補強是另一個有明確教學目的的片段，片內維持風格一致；補強版本保留原影片與來源關聯，供未來相同需求重用。

對話需要保留教材／單元、正在觀看的影片與版本、重點或時間位置、尚未理解的概念及風格偏好。重用以教學內容確實對應為前提；學生只說「這裡不懂」而位置不明時，先問一個定位問題，不能擅自整片重製。

目前程式證據：`workbench/server.py` 的 `ask()` 依問題匹配單元內的 story／highlight，回傳既有影片；`workbench/web/js/pages/library.mjs` 的 `showAnswer()` 有影片即掛載播放器，缺少影片才提供「生成這段」。2026-10-12 起，`workbench/web/js/pages/chat.mjs` 會先播放既有48秒樣片，支援章節定位、重播、觀看後追問，並把一般問題送至正式 `/ask`；同題換風格只記錄補強需求，明示尚未生成。對話狀態、另一版本查找及補強片生成派工仍未接入。

## 所有風格都必須遵守的驗收

1. 實測文字框不只檢查 panel 邊界，也檢查可見文字兩兩相交。數值標籤與值應有各自布局空間，避免大字和絕對定位狀態共用同一區域。字級改動要重新量測。
2. 動畫由語意事件驅動。條件分支、更新、返回、離開標籤不能在尚未介紹／執行時先顯示；箭頭末端不能早於路徑建立。建立概觀和實際走讀的揭露規則需要明確區分。
3. 公式形變先讓不匹配項退場，再讓保留符號移動，最後帶入新值；即使是轉場，也要檢查可見符號互撞。
4. 依字幕／講解事件設計資訊出現時間；逐幀檢查、冷與倒序 seek、成片擷取和縮小預覽都要驗。抽查幾張末幀不能證明全部過程正確。
